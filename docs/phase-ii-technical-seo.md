# Phase II technical SEO implementation

The recovery point for this release is production commit `8f13666da21eb2f542bcc83928efbcb0d3ab744a` and Cloudflare version `c87287f2`. The launch procedure uses the existing Git-connected Workers deployment and one production merge. The Phase I browser, asset and paid-call regression suites remain part of release validation.

## Architecture and indexing policy

- `src/config/routeRegistry.ts` draws route types, sources, hierarchy, language availability and compatibility aliases from the existing content and campaign records. `scripts/generate-navigation.mjs` emits a compact client lookup and a complete build inventory. Browser routing and content rendering still use Phase I page chunks.
- `scripts/prerender.mjs` writes the sitemap and redirects from the registry. It rejects disagreements between declared indexing policy and rendered metadata. The sitemap retains `/sitemap.xml`, includes all 224 indexable routes and carries reciprocal language annotations. Publication dates and historical blanket timestamps do not establish reliable last modification dates. The registry supports explicit verified dates. One sitemap is sufficient at this size.
- Two legal pages were already public and indexable. They now appear in the XML sitemap. The 15 paid pages and 30 compatibility aliases still load and declare `noindex, follow`. Each alias points at the respective primary paid canonical. The two entry-hub spelling variants redirect to the canonical services directory. Missing routes use the existing genuine 404.
- Canonical directory paths end in a slash. Internal links, SPA transitions, metadata and breadcrumb URLs use the same format. Normalized links preserve queries and fragments. The public HTML directory is linked from the footer and covers organic content. Paid destinations remain independent of organic navigation.
- Shared head descriptors serve static rendering and hydration. A resolved single page record supplies the canonical, robots, social metadata and language annotations. Shared breadcrumbs give template relationships meaningful accessible links. City and county LocalBusiness graphs retain their existing entities. The limited adjustments to page and breadcrumb identifiers preserve their canonical relationship.
- Phase II changes targeted the organic car key replacement, automotive overview, lockout service and public sitemap metadata. Existing page data and customer intent support the distinctions. Most search data is still sparse. Retain the established page-specific metadata while Google recrawls the technical fix.
- `scripts/check-seo.mjs` validates the build inventory, sitemap, canonical links, reciprocal hreflang, metadata, schema references, accessibility structure and internal navigation graph. It distinguishes heading-level advisories from critical publishing errors. `scripts/check-seo-browser.mjs` compares static and hydrated metadata and validates bilingual in-page navigation. Reports can be regenerated by running the build and SEO check and retaining `src/generated/technical-seo-report.json`.
